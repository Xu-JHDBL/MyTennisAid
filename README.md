# 🎾 MyTennisAid — 网球精彩回合自动识别

从固定机位（正后方）拍摄的网球全场录像中，自动识别"多拍回合 / 高质量拉球"片段并剪辑出来，免去人工从头翻到尾找精彩片段。

---

## 1. 问题背景与核心难点

网球初学者常把整场练习用手机录下来（单场 40 分钟以上），其中大量时间是捡球、休息等无意义片段。要自动找出"精彩回合"，面临两个关键难点：

1. **如何判断"哪里在打回合"**：回合 = 短时间内连续的多次击球。
2. **如何排除隔壁场地的干扰**：相邻网球场距离很近，隔壁的击球声会被清晰录进本场录像，造成"隔壁在打、本方没打"的假回合。

本项目针对**固定机位、正后方视角、画面里只有本方场地**的典型录制场景，给出了一套**纯本地、无需 GPU、无需训练**的轻量方案。

---

## 2. 整体思路：声音找候选，画面做判定

核心思想是一句话：**音频负责"找出哪里像在打球"，画面负责"确认是不是你们自己在打"。**

| 信号 | 作用 | 为什么可靠 |
|---|---|---|
| **击球声（音频）** | 生成候选回合 | 击球"啪"声是短促尖锐的瞬态，能量高、易检测，且不依赖画面 |
| **画面运动量（视觉）** | 过滤隔壁串音 | 本方回合时球员在跑动挥拍（运动量大）；隔壁串音时本方球员站着不动（运动量小） |

其中"画面运动量"正是解决隔壁串音的关键：**隔壁的球不会出现在本方镜头里**，所以本方回合的画面活跃度明显高于"站着等球"的隔壁回合。

---

## 3. 处理流程

```
输入视频
   │
   ├─ ① 提取音轨（ffmpeg，mono 24kHz）
   │       ↓ 高通滤波 + 短时能量 + 自适应阈值
   │   检测击球"啪"声 → 得到击球时间点序列
   │       ↓ 按击球间隔聚类（间隔 > 4s 视为回合断开）
   │   候选回合（拍数 ≥ 6）
   │
   ├─ ② 抽取低分辨率代理视频（320px / 6fps）
   │       ↓ 逐帧灰度帧差 → 画面运动量时间线
   │   对每个候选回合算「运动比」= 回合内平均运动量 / 全场中位数
   │       ↓ 运动比 ≥ 1.30 → 判为本方回合，否则丢弃
   │
   └─ ③ 输出片段起止时间（前后各留 2 秒），ffmpeg 流复制剪辑
```

中间产物（音轨、击球点、代理视频、运动量）全部写入**临时目录**，处理完自动删除；最终只在视频同目录下生成 `<视频名>_MyTennisAid/`，里面**只保留剪辑好的 mp4 片段**。

---

## 4. 关键算法细节

### 4.1 击球点检测（音频）

- **预处理**：4 阶 Butterworth 高通滤波（截止 300Hz），滤掉风声、低频环境嗡鸣，突出击球声的高频瞬态。
- **能量包络**：短时 RMS（窗 20ms、帧移 10ms）。
- **自适应阈值**：背景 = 5 秒滚动**中位数**（对击球尖峰鲁棒）；击球点判定为能量 > `背景 × 4.0 + 绝对下限`。
- **去重**：两次击球最小间隔 0.30s，避免同一击球的混响被重复计数。

### 4.2 回合聚类

对击球时间点做差分，**间隔 > 4 秒**即认为"这个回合结束、下一个开始"（捡球/休息的间隔通常远大于 4 秒）。每个候选回合要求**拍数 ≥ 6**（对初学者而言，6 拍已经是"多拍回合"）。

### 4.3 画面运动量门控（核心判据）

- 抽一段 320px 宽、6fps 的低分辨率代理视频（旋转无关，仅看运动量）。
- 逐帧计算灰度帧差均值，得到整场运动量时间线。
- 对每个候选回合窗口取运动量均值，除以全场中位数得到「运动比」。

**运动比的分层**（经真实视频标注验证）：

| 运动比 | 含义 | 判定 |
|---|---|---|
| ≥ 1.35 | 球员在跑动挥拍 | ✅ 本方回合 |
| ≤ 1.24 | 球员站着等球（隔壁在打） | ❌ 丢弃 |

阈值取 **1.30**，位于两层之间，留有安全边距。

> 为什么不用"击球响度"来区分本方/隔壁？因为本方**近端球员**的击球很响、**远端球员**本来就轻，天然有 5~10 倍响度差，与隔壁混叠成单峰分布，无法二分。

## 5. 阈值选取与实验

在真实录像（1080p/60fps、42 分钟、正后方固定机位）上，音频检测到 **274 次击球、聚成 12 个候选回合**（≥6 拍），画面门控后保留 4 个——与人工标注结果 **100% 一致**。

关键发现：音频检测出的"拍数最多的回合"（12 拍、11 拍）**恰恰是隔壁场地的**（隔壁水平更好、回合更长），而本方精彩回合实际只有 6~8 拍。这进一步印证了"仅靠音频拍数不够，必须用画面运动量判定"。

主要可调参数（`MyTennisAid/pipeline.py` 的 `CFG`）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `min_hits` | 6 | 候选回合最少拍数 |
| `rally_gap` | 4.0 | 回合断开间隔（秒） |
| `motion_ratio` | 1.30 | 运动量门控阈值 |
| `threshold_ratio` | 4.0 | 击球能量阈值倍数 |
| `proxy_fps` / `proxy_scale` | 6 / 320 | 运动分析代理视频参数 |

## 6. 探索过但未采用的方案

| 方案 | 结论 |
|---|---|
| 通用 YOLOv8 的 `sports ball` 类 | COCO 通用模型对网球检测不可靠，假阳性多，弃用 |
| TrackNet 网球专用检测 | argmax 峰值其实很干净（有球 242 / 无球 0），但纯 CPU 上约 1.2s/帧太慢；且从正后方拍球沿光轴飞，检出率偏低。留作后续增强方向 |
| 击球响度二分 | 单峰分布，无法区分（见 4.3） |
| 画面帧差均值 vs 掩码面积 | 两者分层一致，最终用帧差均值（更简单） |

## 7. 使用方法

**方式一：exe（推荐，无需 Python）**

1. 双击 `dist/MyTennisAid.exe`
2. 自动打开浏览器（如未打开，访问 http://127.0.0.1:7860）
3. 填写视频完整路径（或上传），点「开始分析」
4. 查看结果、点击下载；片段同时已保存到**视频同目录**的 `<视频名>_MyTennisAid/` 下

**方式二：命令行（开发）**

```bash
pip install -r requirements.txt
python server.py
# 浏览器打开 http://127.0.0.1:7860
```

> 全程本地运行，视频不会上传到任何服务器；无文件大小限制（仅受磁盘空间与处理时间约束）。

### 重新打包 exe

```bash
pip install pyinstaller
pyinstaller MyTennisAid.spec   # 需在项目根目录放置 ffmpeg.exe
```

## 9. 局限与后续方向

- **阈值依赖机位**：当前阈值 1.30 是在"正后方、固定机位、画面只有本方场地"场景下校准的；换机位/角度可能需要重新校准。
- **同时打球的邻场**：若本方与隔壁同时打回合，音频会混叠，运动量门控无法完全拆开（需要逐拍级的球检测，即后续 TrackNet 方向）。
- **高质量"打分"**：当前以"拍数"为主要精彩度指标，尚未对球速、落点、回合质量做精细评分。
- **后续**：多视频校准阈值、TrackNet/ONNX 球检测增强、拍数与运动量的综合打分。
